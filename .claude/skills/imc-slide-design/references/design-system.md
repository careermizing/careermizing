# 디자인 시스템

두 레퍼런스(아르르 푸드, 에너지플러스)에서 공통으로 확인된 문법만 추렸다. 값은 `scripts/imc_deck.py`의 `TOKENS`가 기준이다.

## 1. 색

| 토큰 | HEX | 용도 |
|---|---|---|
| primary | 138CB0 | 핵심 막대, 필(캡슐) 헤더, 강조 글자, 핵심 칩 |
| deep | 0B5A73 | 표 헤더, 짙은 필, 표지 배경 |
| mid | 7FA9B8 | 보조 칩, 다크 장표의 보조 면 |
| tint / tint2 | D9EEF4 / EAF6FA | 카드·강조 열 배경, 점선 박스 안쪽 |
| hilite | C9ECF5 | 제목 하이라이트(형광펜) 배경 |
| ink / text | 111111 / 2A2A2A | 제목 / 본문 |
| mute | 8A8F94 | 출처·캡션·보조 텍스트 |
| gray / gray2 | E7E7E7 / F0F0F0 | 비강조 막대, 비교 대상 칩, 줄무늬 |
| bg | F6F6F4 | 기본 배경 (순백 아님) |
| dark | 262A2D | 다크 장표 배경 (문제 정의·프로그램 상세) |
| alert | C62828 | 이탈·문제 수치. **한 장표에 한두 곳만** |

규칙
- 한 덱 = 주색 한 계열. 브랜드가 바뀌면 `TOKENS`의 primary/deep/mid/tint/hilite 5개만 교체한다(`Deck(tokens=load_tokens('tokens.json'))`로 JSON 오버라이드, 예시는 `tokens.example.json`).
- 강조는 "진한 주색 vs 회색" 대비로 만든다. 색을 늘려서 구분하지 않는다.
- 빨강은 문제의 크기를 보여주는 숫자에만. 장식에 쓰지 않는다.

## 2. 타입

폰트: Pretendard (Regular/Medium/SemiBold/Bold). 모든 run에 latin/ea/cs 모두 지정.

| 요소 | 크기 | 굵기 | 비고 |
|---|---|---|---|
| 섹션 태그(좌상단) | 12 | Bold, 주색 | `시장분석 \|` 형태, 페이지 번호는 우하단 작게 |
| 장표 제목 | 26 | Bold | 가운데 정렬, 2줄 이내, 자간 −0.5 |
| 필 헤더 | 15 | Bold, 흰색 | 캡슐, 주색/짙은 주색 |
| 본문 | 14–16 | Regular | 줄간격 1.35–1.4 |
| 표 | 13.5 | Regular | 헤더 Bold 흰색 |
| 말풍선 | 14.5 | Regular | 핵심어만 Bold |
| 결론 바 | 19 | Bold | 핵심 구절 하이라이트 |
| 출처 | 10 | Regular, mute | 항상 해당 근거 바로 아래/우상단 |
| 부록 | 9–11 | | 부록에서만 작게 허용 |
| 프로그램명(다크) | 44 | Bold | 자간 −1.5, 장표당 하나 |

- 한글은 자간을 −0.2~−1.5로 약간 조인다(제목일수록 더). 숫자 KPI는 크게(32–60) 두고 단위·라벨은 12–14로 작게.
- 마크업: `**굵게+주색**`, `==형광 하이라이트==`, `\n` 줄바꿈.

## 3. 레이아웃

- 슬라이드 13.333×7.5in. 좌우 여백 0.6in.
- 제목 영역: 섹션 태그 y≈0.3, 제목 y≈0.78(2줄 기준 하단 ≈1.7).
- 제목 아래 0.35in 후 필 헤더 → 필 아래 콘텐츠. 필은 콘텐츠 블록 폭에 맞춘다.
- 하단 결론 바: y = 7.5 − 1.1, 높이 0.66. 그 위로 콘텐츠를 끝낸다.
- 정보 밀도: 한 장표 블록 3~4개 이하. 레퍼런스 덱은 여백이 넉넉하며 표 외에는 꽉 채우지 않는다.
- 다크 장표(`dark`)는 전환점(문제 정의, 프로그램 상세)에만. 연속 3장 이상 쓰지 않는다.

## 4. 문장 규칙 (레퍼런스 공통)

- 제목은 명사구가 아니라 **완결 문장**: "오늘의집은 탐색 1위지만, 구매는 여러 채널 중 하나에 머물러 있습니다".
- 제목 하나에 주장 하나. 숫자는 제목에 직접 넣지 않아도 되지만 본문 근거에는 반드시.
- 필 헤더 = 명사구(블록 이름). 불릿 = 해석 문장. 표 셀 = 단어·짧은 구.
- 인용문은 따옴표 없이 말풍선 + 출처(`P1 | 인터뷰`) 캡션. 실제 응답 문장을 다듬되 의미는 바꾸지 않는다.
- "~할 것으로 기대됩니다" 류 추측은 기대효과 칸에만 쓰고, 수치 근거 없이 단정하지 않는다.

## 5. Do / Don't

Do
- 핵심 하나만 진하게 → 나머지 회색
- 장표마다 출처·N 캡션
- 플레이스홀더에 들어갈 이미지 설명 라벨
- 프로그램은 같은 템플릿(이름·슬로건·블록·기대효과)으로 반복해 비교가 되게

Don't
- 아이콘·이모지로 장식 (레퍼런스에 없음)
- 그라데이션·그림자·3D 효과 (그림자는 `phone()` 프레임에만 예외)
- 한 장표에 두 개 이상의 주장
- 12pt 미만 본문 (부록 제외)
- 표에 문장 단위 긴 텍스트

## 6. 이미지·목업 정책

- `image(s, x, y, w, h, label)`: 사선 없는 연한 회색 면 + 점선 테두리 + `[ IMAGE ]` 라벨. 라벨 예: `앱 화면 목업 — A/B 장면 선택 UI`.
- `phone(s, x, y)`: 모바일 프레임. 화면은 비워 둔다.
- 교체 시 같은 크기·위치로 그림만 올리고, 라운드 처리는 `rect(radius=…)` 값을 맞춘다.
