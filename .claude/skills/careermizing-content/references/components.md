# 컴포넌트 인벤토리와 슬라이드 아키타입

Figma에서 반복 등장한 UI 패턴을 "컴포넌트"로, 슬라이드 단위의 조합을 "아키타입"으로 정리했다. 렌더러(`scripts/render_carousel.py`)의 슬라이드 `type` 이름과 1:1로 맞춰 두었으니, 기획 단계에서 아키타입 이름으로 바로 구성안을 쓰면 된다.

## 2. 슬라이드 아키타입

렌더러 `type` 값과 역할. 각 아키타입은 "무엇이 들어가는가 → 순서 → 비고".

| type | 아키타입 | 구성 (위→아래) |
|---|---|---|
| `cover_photo` | 포토 표지 | 사진 + 오버레이 → (좌상단 로고) → [서브(위) 42~60 Regular/SemiBold "아.. 직무 경험 없는데, 어떡하지?"] → 헤드라인 Black 86~110 2~3행 (하단 정렬, y≈700~980) → [서브(아래) 45 SemiBold] → 출처 캡션 |
| `cover_typo` | 타이포 표지(다크) | 브랜드 마크 + 페이지 → eyebrow "채용 담당자 :" → 질문 Black 74~82 3행 → 액센트 바 → 훅 Bold 40 2행 → 소형 Medium 28 2행 |
| `cover_promo` | 프로모션/공채 표지 | 사진 + 오버레이 → (접수기간 SemiBold 50 .7) → 헤드라인 ExtraBold 105 2행(1행 기업명 포인트색) → 설명 Medium 56 → (배지 "무료 모의면접 1회") → 로고 + 출처 |
| `text` | 텍스트 본문 | 브랜드 마크 → 헤드라인 → 서브 → 본문 단락 1~3 (또는 이미지) → 결론 → 면책 |
| `cards` | 카드 리스트 | 헤드라인 → 서브 → 번호 카드 2~5개 → 결론/하이라이트 박스 |
| `steps` | 스텝/프로세스 | 헤드라인 → 서브 → 번호 사각/원 + 라벨 row 4~5개 → (무료 바) |
| `compare` | 2단 비교 | 헤드라인 → 좌 카드(칩+제목+불릿) | 우 카드(칩+제목+결과 pill) → 결론 |
| `before_after` | BEFORE/AFTER 세로 | 헤드라인 → BEFORE 박스(취소선) → AFTER 카드(태그 pill + 문단 + 디바이더) → 결론 |
| `answer` | 실제 답변 예시 | 헤드라인 "그럼 면접에서는 / 이렇게 말할 수 있어요" → 서브 "○○ 지원자 · 가상 답변" → 답변 카드(3문단, 우측 태그) → 결론 "📌 저장해두고…" → 면책 |
| `chat` | 대화 흐름 | 타이틀 "면접" → 지원자/면접관 카드 교차 4개 → 결론 |
| `table` | 표 | 헤드라인 → 서브 → 표(헤더 + 행) → 결론 |
| `datalist` | 다크 데이터 리스트 | 로고 → 헤드라인 64 → 서브 → 행 N개(날짜|기업|메모|상태) → (강조 테두리) → 각주 |
| `checklist` | 체크리스트 | 헤드라인 → 체크 행 5개 → 네이비 결론 박스 |
| `worksheet` | 빈칸 워크시트 | 헤드라인 → 카드 3개("1 라벨 / 문장 ____ / 예)") → 결론 |
| `feature` | 기능 설명 | 칩 "기능 ①" → 헤드라인 72(2행 블루) → 본문 3행 → 캡처/기능 카드 → "* 화면은 이해를 돕기 위한 예시입니다" |
| `benefit` | 혜택/가격 | 칩 → 헤드라인 → 기간 라인 → 가격 행 3개(취소선→0원) → 조건 안내 → 마무리 2문장 |
| `promo_cards` | 다크 프로모션 카드 | 태그 pill → 헤드라인 Black 72~96 → 카드(번호 옐로 + 제목 + 설명) 2~3 → 옐로 강조 문장 + 캡션 출처 |
| `promo_cta` | 프로모션 CTA(다크) | 칩 "무료로 시작" → 헤드라인 → 체크 리스트 4 → CTA 버튼 → 서브 → 로고 |
| `cta_worksheet` | 마지막 장(워크시트 + 버튼) | 브랜드 마크 + "07 / 07" → 액센트 바 → 헤드라인 "면접 전에, / 내 답변 3줄만 / 적어보세요." → 워크시트 카드 → 제품 동선 한 줄 "경험정리 → JD 기반 경험 선택 → 면접 연습" → 버튼 |
| `cta_radial` | 라디얼 CTA(1440) | 캡슐 → 캡처 카드 → 헤드라인(증거 2행 + 그라디언트 1행) → 민트 바 + "댓글에 "키워드" 남기면 / … 링크 드릴게요." |
| `promo_brand` | 홍보 1장(포토 다크) | 칩 "커리어마이징" → Inter Bold 56 2행 "커리어마이징에서는 / 이 모든 걸 무료로 할 수 있다고?" → 서브 → 로고 |
| `service_placeholder` | 서비스 장(캡처 자리) | 캡슐 → 캡처 자리 → 헤드라인 "1.5만 건의 대기업 합격자료로 만들어진 / 대기업 특화 취준 AI, 커리어마이징" → 세로바 + 문장 |
| `note` | 검수 메모 | 크림 bg, 메모 + 캡션 초안 + UTM |

| P | 취준팁/면접팁 (7P) | 정보성 (6~7P) | 기업 공채 (6P) | 프로모션 (8P) | 기능 홍보 (6~8P) |

## 5. 표준 블록 라이브러리 (std, 2026-11 모범 사례 기반) — 우선 사용

`base-grammar.md`의 고정 문법을 입힌 블록이다. **한 장에 블록을 자유롭게 쌓을 수 있다**(`std_stack`의 `blocks` 배열). 모범 사례에서 왔지만 순서·조합은 내용에 맞게 바꾼다.

| kind | 생김새 | 이럴 때 | 모범 사례 출처 |
|---|---|---|---|
| `image` | 600×431 r28 짤/사진(자리면 점선) | 공감·상황 제시 | 주변평가 P02, 공백기 P02 |
| `quote` | 테두리 3px `#B9CDF9` 카드 + 회색 라벨 + 손글씨 블루 | 흔한 답·속마음·오답을 보여줄 때 | 주변평가 P02 |
| `cards` | 번호 카드 3장 + ▼ 연결, 마지막 강조 | 이유·기준 2~4개를 순서대로 | 주변평가 P03 |
| `table` | 2열 표(머리글 + 3px 검정 선) | A→B 매핑(들은 말→행동, 방법→한계) | 주변평가 P04 |
| `bar` | 좌측 블루 세로 바 + 36px 문단 + 형광펜 | 실제로 말하는 답변 | 주변평가 P05 |
| `gray` | `#F2F4F8` r28 라벨+문장 | 덧붙일 한 문장, 보조 팁 | 주변평가 P05 |
| `worksheet` | 테두리 카드 3개, 빈칸 밑줄, "예)" | 독자가 직접 채우게 할 때 | 주변평가 P06 |
| `flow` | 중앙 정렬 박스 3개 + ↓, 가운데 강조 | 답변·과정 순서 | 공백기 P03 |
| `compare` | BEFORE(회색, 취소선 요약) / AFTER(블루 틴트) 2단 | 같은 소재의 전후 비교 | 공백기 P04 |
| `pairs` | 회색 카드 ▼ 블루 카드 쌍 | "일반적인 것 vs 우리 것"을 실물 예시로 | (신규, compare 변형) |
| `panel` | 블루 틴트 패널 + 태그 pill 행 | 답변을 구조 태그로 분해 | 공백기 P05 |
| `xlist` | × / ✓ 리스트 + 구분선 | 하지 말 것, 안 해도 되는 것 | 공백기 P05 |
| `text` | 32px 문단 | 짧은 설명이 꼭 필요할 때 | — |

장 단위 타입: `std_cover`(사진 표지), `std_stack`(헤드라인+서브+블록들+결론), `std_cta`(다크 체크리스트+버튼, 공백기 P06), `std_service`(다크 서비스 캡처, 주변평가 P08). 하위 호환으로 `std_meme / std_cards / std_table / std_answer / std_worksheet / std_flow / std_compare / std_pairs / std_panel`도 그대로 쓸 수 있다.

### 새 블록이 필요하면

내용에 맞는 블록이 없으면 만들어도 된다. 조건은 셋: ① 글자 크기·굵기·색은 `base-grammar.md` 표의 역할 중 하나를 그대로 쓴다 ② 테두리 3px `#E3E8F0`/r28~36 또는 블루 틴트 면 중 하나로 감싼다 ③ 한 장에 블록은 두 개까지. 새 블록을 쓰면 `std_format.py`의 `block()`에 추가하고 이 표에 한 줄 적는다.

## 6. 흐름 설계 (유동) — 템플릿을 고르지 말고 질문으로 정한다

모범 사례 두 편의 흐름은 이렇다. **참고용이지 정답이 아니다.**

- 주변평가(8P): 사진 표지(질문+오답) → 공감 짤 + 흔한 답 → 면접관이 보는 것 3가지 → 칭찬↔행동 표 → 실제 답변 → 빈칸 3줄 → 서비스
- 공백기(6P): 사진 표지(면접관 대사+속마음) → 흔한 답 짤 + 면접관 다음 질문 → 답변 순서 3단 → BEFORE/AFTER → 예외 상황 + 하지 말 것 → 다크 체크리스트 CTA

새 콘텐츠는 아래 질문에 답하면서 장을 배치한다.

1. **독자가 첫 장에서 "내 얘기다"라고 느낄 장면은?** → 표지(면접관 대사·속마음·오답 중 하나)
2. **지금 독자는 무엇을 잘못 알고 있거나 막혀 있나?** → 공감/문제 장 1장(짤+quote, 또는 table, 또는 xlist)
3. **관점을 바꿔줄 핵심 한 문장은?** → 그 문장이 결론이 되는 장 1장(cards/flow)
4. **그걸 눈으로 증명할 실물은?** → 비교·예시 장(compare/pairs/bar). 설명보다 실물을 우선.
5. **독자가 바로 해볼 행동은?** → worksheet 또는 std_cta 체크리스트
6. **제품이 들어갈 자리는?** → 취준팁은 마지막 1장만. 프로모션은 4장 이후부터 자연스럽게.

규칙: 한 장 한 메시지, 6~8장, 같은 블록을 연속 3장 이상 반복하지 않기, 직전 게시물과 표지 방식이 겹치지 않게.
