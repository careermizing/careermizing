# 자체 QA · 팩트 체크 · 검수 요청

## 1. 공통 품질 5항목 (운영 문서)

- **Hook**: 보자마자 이유를 알 수 있는가
- **Story**: 한 페이지 한 메시지인가
- **Fact**: 원문 출처와 가상 사례 표기가 맞는가
- **Visual**: 모바일 가독성·짤 의미·이미지 권리 확보 여부
- **CTA**: 제품이 실제 제공하는 내용과 현재 혜택이 일치하는가

## 2. 제출 전 자체 점검 (원문)

- [ ] 표지에 면접 상황·질문·고민이 곧바로 이해된다.
- [ ] 한 장에 핵심 메시지가 하나이고 흐름이 끊기지 않는다.
- [ ] 실전 답변 구조 또는 구체적인 예시가 있다.
- [ ] 공식 기출·합격 기준·수치 등을 출처 없이 단정하지 않는다.
- [ ] 가상 답변을 '가상 예시'로 표시했다.
- [ ] 짤·이미지가 의미에 맞고 출처·사용권을 확인했다.
- [ ] 휴대폰에서 텍스트가 읽히며 오탈자가 없다.
- [ ] CTA·가격·무료 횟수 등 현재 실제 제공 기능과 일치한다.
- [ ] Figma 편집본·캡션·참고 링크가 준비됐다.

정보성 추가:
- [ ] 원문 출처·기준일·적용 대상과 사실관계를 확인했는가
- [ ] 오래된 공고·마감된 전형을 현행처럼 표현하지 않았는가
- [ ] 정보 요약만 하지 않고 취준생이 왜 알아야 하는지 전달했는가

프로모션 추가:
- [ ] 현재 실제 UI·무료 권한과 1:1 대조
- [ ] 가격 표기: 정가 기준·할인율·기간·기존 고객 안내, 선착순 문구 없음
- [ ] 추가 자료 약속 없음(확정 전 고지 금지)

## 3. 팩트 검증 규칙

| 유형 | 기준 |
|---|---|
| 공식 질문 | 출처가 확인된 기관/기업의 예시라고만 표현 |
| 실제 기출·빈도 | 근거 없으면 '대기업 공통 기출' 등의 단정 금지 |
| 합격 사례·성과 | 실제 자료·이용 권한 확인 전 외부 홍보에 사용하지 않음 |
| 가상 사례 | 본문에 반드시 '가상 예시' 표시 |
| 기능/가격/혜택 | 게시 당일 앱 기능·정책 확인, 추정하지 않음 |
| 내부 데이터 | 직접 열람하지 않은 수치는 "보유·검증했다고 주장 금지" |
| 과거 통계 | "과거 조사 수치이므로 올해 채용 전체에 일반화하지 않는다" — 본문 미노출 |

Evidence Pack 관행: 출처마다 **열람일** 명시, "확인 Fact / 취준생 의미 / 콘텐츠에 실제 사용할 근거 / 주의(확대 해석 금지)" 4항 기술.

## 4. 디자인 QA (이 스킬 고유)

- [ ] 캔버스 1080×1350(또는 시리즈 규격) 통일, 비율 혼용 없음
- [ ] 포인트 블루 1종으로 통일(#2F5CE0 기본), 기업 CI는 포인트만
- [ ] 헤드라인 2행 이내(표지 3행), 본문 36px 이상, 면책 21px 이상
- [ ] 좌우 마진 64~80, 콘텐츠 폭 ≤ 936
- [ ] 페이지 번호 "0N / 0M"이 모든 장에, 번호와 총 장수 일치
- [ ] 브랜드 마크 위치 일관(라이트 좌상단 / 포토 표지 좌상단 로고 / 1440 좌하단)
- [ ] 사진 장마다 출처 캡션, 캡처 장마다 "* 화면은 이해를 돕기 위한 예시입니다"
- [ ] 답변 예시 장마다 면책 ※
- [ ] 직전 콘텐츠와 "사진 표지 / 3칸 카드 / Before·After" 레이아웃 연속 반복 아님
- [ ] CareerMizing 철자(M 대문자), 기능명 공식 표기

## 5. 검수 요청 템플릿

```txt
[콘텐츠 검수 요청 | 제목]
Figma: [원본 링크]
캡션: [내용 또는 링크]
핵심 메시지: [한 문장]
기획안 대비 변경: [최대 2줄]
이미지·근거: [출처 링크]
확인 필요한 사항: [최대 3개]
자체 QA: [완료 / 아직 확인 안 된 항목]
```

피드백 형식 예:
```txt
[검수 결과] 부분 수정
P1: 표지가 길어 공감이 약함 → 실제 면접관 질문 1문장으로 압축
P3: "모든 면접관" 근거 없음 → 삭제 및 확인 가능한 범위만 표현
P5: 이미지가 본문을 가림 → 기존 2단 비교 컴포넌트 적용
CTA: 현재 실제 제공 중인 기능 기준으로 다시 확인 후 재검수
```

## 6. 상태·네이밍

- 상태 흐름: `Backlog → Researching → Planning → Review 1 → Design → Review 2 → Final → Published` (Published는 게시 URL·일시 확인 시에만)
- Figma 섹션 이름: `[STATUS] YYYYMMDD / 유형 / 주제 (NP)` 예: `[DESIGN] 20261015 / 면접팁 / 왜 당신을 뽑아야 하죠 (7P)`, `[REVIEW] 20261019 / 면접팁 / 우리 회사의 약점은? (7P) · 근거와 톤`
- 프레임 이름: `{시리즈} v{버전} · P{번호} {역할}` 예: `주변평가 v7 · P05 준비 팁 2`, `면접 프로모 05 | 예시 BEFORE/AFTER`
- 검수 메모 프레임: `NOTE · 캡션 & 검수 메모` (폰트 대체 여부, 근거, 수치 확인 필요, 가격 기준, 금지 확인, 캡션 초안, UTM)
