# PART 2. D-3 → D-day 공통 루틴

> 아래 루틴을 **회사마다 한 번씩** 돌립니다. 램리서치는 10/4~10/7, AMAT은 10/9~10/12입니다.

## D-3: 초안을 "완성"으로 선언하는 날

**목표: 모든 문항에 끝까지 쓴 글이 있는 상태로 만들기.** 이날 이후로는 소재를 바꾸지 않습니다.

| 시간 | 할 일 | 완료 기준 |
|---|---|---|
| 오전 | 문항별 소재 확정 | 문항마다 경험 1개가 정해지고, 한 회사 안에서 같은 경험이 2번을 넘지 않음 |
| 오후 | 빈 문항부터 끝까지 쓰기 | 모든 문항이 글자 수 제한의 90% 이상 채워짐 |
| 저녁 | 문항별 첫 문장만 모아서 읽기 | 첫 문장만 읽어도 무슨 경험인지, 어느 직무인지 보임 |

**D-3 체크리스트**
- [ ] 모든 문항에 초안이 있다
- [ ] 소재가 확정됐다 (이후 바꾸지 않는다)
- [ ] 글자 수 제한을 넘는 문항이 없다 (공백 포함 기준인지 사이트에서 확인)
- [ ] 첫 문장 모음만 읽어도 지원 직무가 보인다

> ⚠️ D-3에 "더 좋은 경험이 있을 것 같다"는 생각이 들어도 소재를 바꾸지 마세요. 소재를 바꾸면 D-2·D-1 점검을 처음부터 다시 해야 하고, 그 시간이 남지 않습니다.

## D-2: 사실과 숫자를 검증하는 날

**목표: 면접에서 "그게 정확히 무슨 뜻이죠?"라는 질문을 받아도 막히지 않을 글로 만들기.**

| 점검 | 방법 | 통과 기준 |
|---|---|---|
| **숫자 점검** | 글에 나온 숫자를 모두 표시 | 모든 숫자에 "어떻게 측정했는지" 한 문장으로 답할 수 있음. 추정치는 "약"을 붙임 |
| **골격 점검** | 경험 문단마다 6단계 표시 | 문제 정의 → 진단 근거 → 조치 → 검증 → 재발 방지 → 직무 연결 중 빠진 단계가 없음 |
| **회사 정보 점검** | 회사에 대해 쓴 문장을 모두 표시 | 출처를 댈 수 있음. PART 4의 틀리기 쉬운 정보에 해당하지 않음 |
| **직무 언어 점검** | 장비 계열(FSE·CE·FE)인지 공정 계열(PSE·PE)인지 확인 | 장비 계열 지원서에 "레시피 최적화", "공정 창" 같은 공정 계열 언어가 중심에 있지 않음 |
| **나 vs 팀 점검** | 팀 경험 문단에서 주어 확인 | "우리는"으로 끝나는 문장마다 "그중 내가 한 일"이 보임 |

**D-2 체크리스트**
- [ ] 문단마다 숫자가 1개 이상 있고, 모두 측정 방법을 설명할 수 있다
- [ ] 경험 문단에 진단 근거·검증·재발 방지가 모두 있다
- [ ] 회사 정보 문장에 출처가 있다
- [ ] 지원 직무의 언어로 썼다
- [ ] 팀 경험에서 내 역할이 분리돼 있다

| 오후 | **회사명·직무명 검색** | 아래 검색어를 문서 전체에서 찾아 지원 회사 것만 남았는지 확인 |

| 저녁 | **업로드 리허설** | 지원 사이트에 로그인해 입력 칸, 첨부 형식, 임시저장 여부를 미리 확인 |

**회사명·직무명 검색어**

> 램리서치 · Lam · LAM · 어플라이드 · Applied · AMAT · 도쿄일렉트론 · TEL · FSE · CE · FE · PSE · PE · FPE

**D-1 체크리스트**

- [ ] 지원동기가 3초 테스트를 통과한다 (램리서치는 마지막 문장 모아 읽기)
- [ ] 다른 회사 이름과 직무명이 하나도 없다
- [ ] 최종본을 두 곳 이상에 저장했다
- [ ] 지원 사이트의 입력 형식과 첨부 형식을 확인했다
