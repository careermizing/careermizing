# 1. `careermizing-content/SKILL.md`

## 커리어마이징 콘텐츠 에이전트

취준생을 위한 커리어마이징 인스타그램 캐러셀을 **기획안 → 장별 카피 → 디자인 스펙(JSON) → 미리보기 PNG → 캡션 → QA**까지 만든다. 원천은 Figma 「26 하반기 인스타그램 콘텐츠」 440여 장과 Notion 운영 SOP를 역설계한 `references/`다. 레퍼런스에 없는 규칙을 지어내지 말고, 모르면 레퍼런스를 먼저 연다.

### 왜 이 순서인가

이 채널은 "휘발성 바이럴"이 아니라 **저장할 만한 전문 정보로 신뢰를 쌓아 프로필 → 가입**으로 보내는 채널이다. 그래서 (1) 입구는 취준생의 고민처럼 쉽게, (2) 본문은 근거와 실제 발화로 깊게, (3) 제품은 마지막 장에서만, (4) 모든 수치·기출·가격은 확인된 것만 쓴다. 디자인은 네이비·화이트·블루 한 벌로 통일돼 있어 "커리어마이징 것"으로 보이게 하는 게 핵심이다.

### 고정과 유동

- **고정(기본 문법)**: 카피톤, 글자 크기·굵기, 색, 여백, 결론·면책 패턴. `references/base-grammar.md`의 수치를 따른다. 기준점은 모범 사례 「주변에서는 본인을 어떻게 평가하나요?」와 「공백기가 있네요?」.
- **유동(구성)**: 어떤 블록을 쓰고 몇 장을 어떤 순서로 풀지는 내용과 방향에 맞게 정한다. 모범 사례의 장 순서를 복제하지 말고 `references/components.md` §6의 흐름 설계 질문으로 정한다. 맞는 블록이 없으면 기본 문법 안에서 새로 만든다.

### 작업 흐름

1. **유형 판정** — 요청을 넷 중 하나로 분류하고 해당 플레이북을 읽는다.
   - 취준팁·면접팁·정보성(일정/자격증/전형) → `references/content-types/job-info.md`
   - 프로모션(자료·플랜·기능 리뉴얼 판매) → `references/content-types/promotion.md`
   - 기업별(공채 오픈·D-3·채용 뉴스·기업 맞춤 기능) → `references/content-types/company.md`
   - 기능 홍보(출시·리뉴얼 공지) → `references/content-types/feature.md`
   어느 유형이든 `references/base-grammar.md`(고정 문법)와 `references/brand-voice.md`(톤·금지 표현·기능 명칭)는 반드시 읽는다.
2. **기획안(Brief)** — Layer / Persona / Moment / Pain·Question / One Sentence Insight / Hook 3안(A 최종·B 공감형·C 저장형) / Evidence Pack(출처+열람일, 미열람 데이터 명시) / Carousel Flow(장당 한 문장) / Proof(가상 예시 표시) / Main CTA 1개 / Success Metric. 사용자가 기획안을 이미 줬으면 빠진 필드만 채운다.
3. **장별 카피** — `references/components.md` §4의 서사 표로 장수와 역할을 정하고, 장마다 `메인(2행) / 서브 / 본문 / 하단 결론 / 면책 / Visual(아키타입)`을 쓴다. 톤은 brand-voice.md §2~§6. 예문이 필요하면 `references/copy-examples.md`.
4. **디자인 스펙** — 기본은 표준 블록(`std_cover`, `std_stack` + blocks, `std_cta`, `std_service`)으로 쓴다. 예시는 `assets/example-std-spec.json`(모범 사례 재현). 1440 프로모션 시리즈를 이어갈 때만 구형 타입(`cover_promo`, `promo_cards`, `cta_radial` …, `assets/example-spec.json`)을 쓴다. 토큰은 `assets/tokens.json`, 수치는 `references/design-system.md`.
5. **미리보기 렌더** — 아래 명령으로 HTML/PNG를 만들고 PNG를 직접 열어 본다. 넘침 경고(WARN)가 나오면 카피를 줄인다. 사용자에게는 PNG(또는 index.html)를 전달한다.
6. **캡션·배포** — `references/caption-guide.md`로 캡션·해시태그·Story 투표·Threads 한 문단을 쓴다. 캡션은 spec의 `caption` 필드에도 넣는다.
7. **QA** — `references/qa-checklist.md`로 자체 점검하고, 결과를 "검수 요청 템플릿" 형식으로 요약한다. 확인 못 한 수치·가격·기능 상태는 **"확인 필요"로 명시**한다(추정 금지).

Figma에 직접 올려야 하면 Figma MCP(`use_figma`, 사전 `figma-use` 스킬 필수)로 1080×1350 프레임을 만들고 섹션 이름을 `[STATUS] YYYYMMDD / 유형 / 주제 (NP)` 규칙으로 붙인다. 캐러셀 끝에 `NOTE · 캡션 & 검수 메모` 프레임을 추가한다.

### 렌더러

```bash
python3 scripts/render_carousel.py spec.json out_dir     # slide-NN.html + index.html + caption.txt
node scripts/snap.js out_dir                            # slide-NN.png (Playwright). 넘치면 WARN 출력
```

- 스펙: `title, canvas("1350"|"1440"), accent, font("pretendard"|"noto"), brand_mark("dot"|"logo"), slides[], caption`.
- 인라인 마크업: `{{포인트색}}`, `**굵게**`, `==형광펜==`, `~~취소선~~`, `[[보통 굵기]]`, 줄바꿈 `\n`.
- 지원 type: `cover_typo cover_photo cover_promo text cards steps compare before_after answer chat table datalist checklist worksheet cta_worksheet promo_cards promo_cta cta_radial promo_brand feature benefit service_placeholder note`. 각 필드는 `scripts/render_carousel.py`의 `build_slide` 분기와 `assets/example-spec.json` 참조.
- 사진·캡처는 `image` 필드에 경로를 넣는다. 없으면 플레이스홀더(회색/네이비 그라디언트)로 렌더되고, 그 자리는 "이미지 교체 필요"로 보고한다.
- 폰트는 Pretendard/SUIT(jsdelivr) → Noto Sans KR(Google Fonts) 순으로 폴백한다. 오프라인이면 시스템 폰트로 렌더되므로 최종본은 Figma에서 확인하라고 안내한다.

### 절대 지킬 것 (brand-voice.md §8 요약)

- '무조건 탈락 / 모든 면접관 / 합격 보장 / 대기업 공통 기출(근거 없음) / 선착순' 금지. 기업 의도 단정 금지.
- 가상 답변은 반드시 "※ 이해를 돕기 위한 가상 답변입니다" 표시. 합격자 답변·실제 기출로 포장 금지.
- 가격·무료 횟수·기능 상태는 게시 당일 기준 확인 전엔 "확인 필요"로. 미배포 기능을 제공 중처럼 쓰지 않는다.
- 사진·캡처마다 출처 캡션 / "* 화면은 이해를 돕기 위한 예시입니다". 무단 인물 사진 금지.
- 제품은 마지막 장(과 홍보 1장)에서만. P1~P3 제품명 노출 없음(취준팁).
- 브랜드 표기 `CareerMizing` / 커리어마이징, 기능명은 공식 명칭(경험정리·마스터 이력서·기업별 이력서·기업분석·자기소개서 AI·면접).

### 산출물 형식

사용자에게 돌려줄 때는 이 순서로: ① 기획안 요약(Insight·Hook 3안·CTA) ② 장별 카피 표(P/역할/메인/서브/본문/결론/면책/아키타입) ③ 미리보기 PNG 경로 또는 첨부 ④ 캡션+해시태그 ⑤ QA 결과와 확인 필요 항목. 렌더하지 않았다면 그 이유를 적는다.

# 2. `careermizing-content/references/base-grammar.md`

## 기본 문법 — 반드시 지키는 것 (고정)

커리어마이징 정기 콘텐츠(취준팁·면접팁·정보성)와 그 문법을 빌리는 프로모션·기능 소개의 **공통 바탕**이다. 기준점은 대표가 모범 사례로 지정한 두 편이다.

- 「주변에서는 본인을 어떻게 평가하나요?」 Figma 978:1640 (8P, 포인트 `#0D5DF1`)
- 「공백기가 있네요?」 [REDESIGN] Figma 871:332 (6P, 포인트 `#2F5CE0`)

> **고정과 유동의 경계.** 이 문서의 수치(글자 크기·굵기·색·여백·톤)는 지킨다. 반대로 어떤 컴포넌트를 쓰고 몇 장으로 어떤 순서로 풀지는 내용에 맞게 정한다(`components.md` §흐름 설계). 두 모범 사례의 장 순서를 그대로 베끼는 것이 목표가 아니다. 더 좋은 구성이 있으면 그걸 쓰되, 아래 문법 안에서 만든다.

### 1. 캔버스·배경

- 1080×1350. 본문 배경은 **흰색 `#FFFFFF`**. 회색·크림 배경은 쓰지 않는다(카드 안쪽 면에만 `#F2F4F8`·`#F3F7FE`·`#F7F8FA`).
- 다크는 두 군데에만: 사진 표지, 마지막 행동 유도 장(`#071022`) 또는 서비스 장(`#0E1530`).
- 한 캐러셀 안에서 포인트 블루는 하나만: `#2F5CE0`(기본) 또는 `#0D5DF1`.

### 4. 카피톤 (바뀌지 않는 부분)

- **헤드라인 2행 공식**: 1행이 상황·질문(검정), 2행이 답·관점(블루). 예: "난감한 이 질문 / **어떻게 답변하고 있나요?**", "찾은 행동을 답변으로 옮기면 / **이렇게 말할 수 있어요**", "공백기 답변, / 이 순서로 정리해보세요."
- **해요체 기본**, 끝을 "~요 / ~세요"로 부드럽게. 결론은 한 문장 판단: "흔한 칭찬이어도 괜찮아요. **그 말을 들은 행동**이 있으면 내 답이 돼요."
- **실제 말투**로 시작: 면접관 대사("채용 담당자 : 공백기가 있네요 뭐하셨어요?"), 속마음("(속마음) 밥먹고 자고 드라마 봤는데요?"), 오답("오답: '착하다는 말을 많이 들었습니다ㅎㅎ (뻘쭘)'").
- 다음 장으로 넘기는 한 줄을 결론에 둔다: "뭐가 다른 지 알려드릴게요", "면접관: 그래서...어떤 준비를 하셨는데요?"
- 짧게. 서브는 한 줄, 카드 설명도 한 줄. 설명이 두 줄을 넘으면 장을 나눈다.
- 금지: 단정·보장·공포("무조건", "모든 면접관", "합격 보장"), 사무적 개념어, 교과서 문장. 가상 답변은 "※ 이해를 돕기 위한 답변입니다" 표기. (상세: `brand-voice.md`)

### 5. 이미지

- 짤·사진을 적극적으로 쓴다(표지 풀블리드, 본문 600×431 r28). 역할은 공감·비교·실전 예시 중 하나.
- 자리만 잡을 땐 점선 상자 + "이미지 자리 (사진·짤로 교체)"로 남기고, 검수 메모에 교체 필요를 적는다.
- 출처 캡션("출처 : 핀터레스트") 필수.

## 커리어마이징 카피 톤 가이드

Figma 캐러셀 약 440장의 실제 카피와 Notion 운영 문서(Hook 5원칙, 사람 말투 기준, 금지 표현)를 합쳐 정리했다.

### 1. 한 줄 요약

> **"실제 자기소개서를 다듬어주는 전문 컨설턴트가, 취준생 옆자리에서 말하듯"** — 내용은 깊고 냉정하게, 입구는 취준생의 고민처럼 쉽게. 과장·보장·공포 없이 근거와 행동으로 말한다.

타깃은 20대 이공계·대기업 준비 취준생이 1차, 직무 중심으로 취업을 준비하는 모든 취준생이 2차. 미디어 입구는 넓게, 본문 깊이는 엔지니어답게.

### 2. 어미와 문장

| 상황 | 어미 | 예 |
|---|---|---|
| 설명·조언(기본) | **해요체** "~해요 / ~예요 / ~돼요 / ~있어요" | "틀린 말은 아닌데, 누구나 비슷하게 말할 수 있어요." |
| 단정·근거·마무리 | 합쇼체 "~합니다 / ~입니다" | "직무가 달라지면 강점으로 꺼낼 경험도 달라집니다." |
| 행동 유도 | "~하세요 / ~해보세요 / ~두세요 / ~끝내세요" | "저장해두고, 내 경험으로 바꿔 말해보세요." |
| 기능 약속(기능 홍보) | "~드립니다 / ~드릴게요 / ~보여드립니다" | "뺀 경험엔 왜 뺐는지 이유를 보여드립니다." |
| 사실 나열·리스트 | **명사형 종결** | "자소서 대신 경험기술문항." / "각 500자." / "확인하고 붙여넣으면 끝." |
| 표지 훅·속마음 | 반말 질문형, 구어 | "아.. 직무 경험 없는데, 어떡하지?" / "근데 그냥 GPT 쓰면 되는 거 아니야?" / "알고 있어?" |
| 면접관 대사 | 존댓말 질문 | "그 조건이 틀어지면 어떤 문제가 생길까요?" |

규칙:
- 한 캐러셀 안에서 해요체를 기본으로 두고, 결론·근거 문장에서만 합쇼체로 힘을 준다. 두 어미가 한 장 안에 섞여도 된다(실제 사례 다수).
- 헤드라인은 2행 × 7~14자. 본문 1행 15~22자, 3행 구성. 한 장에 메시지 하나.
- 반말은 표지 훅(속마음)과 프로모션의 구어 한 줄("…진행하고 있다고??")에서만.
- 느낌표는 캐러셀당 1~2회(이벤트·공채 OPEN). 이모지는 표지/결론에 1개 이하(📌 🔥 ❌ 🥹 👀). 본문엔 기호만(→ ✓ × ▼ ① ②).
- 영문 약어는 그대로(JD, R&D, FSE, DART, BIW), 기업명은 구어 축약(하이닉스, 현대차, 엔솔)을 헤드라인에, 공식 표기(SK하이닉스, 현대자동차, LG에너지솔루션)를 칩·출처·캡션에.

### 3. 헤드라인 공식 (실제 사례)

| 공식 | 예 |
|---|---|
| 면접관 대사 + 속마음 | "채용 담당자 : / 다른 지원자랑 / 차별점이 뭔가요?" + "(속마음) 친구들은…착하다고 하던데?" |
| 오해 깨기 ❌ | "성장 과정 문항은 / '지금까지 있었던 일'을 쓰는 걸까요? ❌" / "서류 하나 붙었다고 / 그 회사 준비에 바로 올인하면 안 돼요 ❌" |
| 상황 선언 + 변화 | "올해 하이닉스 서류, / 완전히 달라졌습니다" / "이제 면접은 / 서류에 쓴 문장을 / 말로 증명하는 자리예요" |
| 조건 + 결과(2행 블루) | "가지고 있는 이력서 하나면, / 하이닉스 양식 그대로" / "찾은 행동을 답변으로 옮기면 / 이렇게 말할 수 있어요" |
| 질문 + 답 | "이 경험은 넣는 게 맞나? / 이번엔 포함 여부도 알려드릴게요." |
| 숫자 발견형 | "면접 복기 15건을 / 다 뜯어보니, / 꼬리질문은 / 딱 5가지였다" |
| 대조형 | "기출은 같아도, / 내 꼬리질문은 달라야 하니까." / "같은 경험인데 / 한 문장 차이로 달라져요" |
| 희소·시급 | "하이닉스 공채 기간엔, / 전부 무료입니다" / "26 하반기 공고, 지금 넘기면 다시 못볼 지도 몰라요" |
| 대체재 비판(완화형) | "질문만 뽑고 끝나면 / GPT와 크게 다를 필요가 없죠" / "아직도 AI에 "기업분석 해줘"만 쓴다면?" |
| 마지막 장 행동 지시 | "면접 전에, / 내 답변 3줄만 / 적어보세요." |

Hook 편집 5원칙(운영 문서 원문): ① 타깃 명확 — 누가 자기 일로 느낄 질문인가 ② 실제 상황 — 면접관의 말투 또는 취준생의 속마음에서 시작 ③ 긴장감 — 어려운 상황·결정 하나를 짧게 압축 ④ 정확성 — '무조건 탈락', '모든 면접관', '합격 보장' 금지 ⑤ 길이 — 큰 제목은 최대 1~2문장.

### 4. 강조 색·굵기에 들어가는 말

- **포인트 블루 span**: 결과/약속/해결("이렇게 말할 수 있어요", "행동 하나", "그때 한 행동", "밝힌 과제", "0원"). 헤드라인 2행 전체 또는 핵심 명사구.
- **Bold(본문색)**: 핵심 명사·수치·데이터 근거("면접 복기 데이터", "각 500자", "경험기술문항").
- **형광펜 `#FFF0A0`**: 결론 문장의 핵심구, 답변 예시의 행동 구절.
- **옐로(다크 프로모션)**: 번호, 할인율, 긴장 문장("③⑤를 비워 두는 순간, 거기서 평가가 갈립니다.").
- **레드**: BEFORE 라벨, "× 없는 실무 경험과 수치를 만들어내지 마세요." 경고 1회.
- **기업 CI 색 span**: "하이닉스가 원하는 역량이 무엇일까" 같은 '기업이 원하는 것' 1구절만.

### 5. 결론·면책·출처 문장 패턴

- 결론(하단 중앙): "'좋은 사람'보다 '이 일을 할 수 있는 근거'를 보여주세요." / "회사명은 짧게, 선택 기준은 분명하게." / "큰 약속 대신, 해본 일과 배울 기준을 연결하면 충분해요"
- 면책(답변 예시가 있는 장마다): "※ 이해를 돕기 위한 가상 답변입니다. 실제 합격 사례가 아닙니다." / "※ 실제로 한 일일 때만 답변에 사용하세요." / "※ 가상 예시 · 해당 활동을 실제로 한 경우에만 활용"
- 캡처 고지: "* 화면은 이해를 돕기 위한 예시입니다"
- 출처: "출처 : 핀터레스트" / "출처: 현대자동차 공식 발표(2026.08.26)" / "근거: 2026 Lam/AMAT 채용자료 · TEL 2026 상반기 채용" / "출처 : LG에너지솔루션 공식 직무소개 … 현재 채용공고가 아닌 직무 설명이며, 기업 · 직무별로 다를 수 있어요."
- 예상치: "최근 3개년 하반기 서류 접수 흐름을 기준으로 한 예상치입니다. 공식 공고 오픈 시 실제 일정으로 교체하세요."

### 2. 테마 5종

콘텐츠는 아래 다섯 테마의 조합으로 만들어진다. **한 캐러셀은 보통 "표지 테마 1 + 본문 테마 1 + CTA 테마 1"**으로 구성된다.

| 테마 | 배경 | 주 용도 | 대표 시리즈 |
|---|---|---|---|

| **B. 라이트 에디토리얼** | `#FFFFFF` / `#F7F9FD` / `#F2F4F8` | 본문 대부분: 취준팁·면접팁·정보성·D-3·기능 설명 | 면접팁 7P 시리즈, 경험정리 Tip, 이력서 기능 오픈 |

선택 규칙:
- 취준팁·면접팁 → 표지 A 또는 C(타이포) / 본문 B / 마지막 C(워크시트+버튼).
- 정보성(일정·자격증 등 데이터형) → 표지 A / 본문 C(다크 리스트) 또는 B(표·타임라인) / 홍보 1장 + CTA D.
- 기업별 공채 → 표지 A(접수기간+기업명) / 본문 A(다크 텍스트)·B(문서형 분석) / 홍보 + CTA D.
- 프로모션 → 표지 A 또는 C / 본문 C(카드 리스트, 옐로 포인트) / CTA C(버튼형) 또는 D.
- 기능 홍보 → 표지 C 또는 D(UI 캡처) / 본문 B(기능 카드) 또는 라이트 블루 그라디언트(중앙정렬 목업) / CTA D.
- 같은 주 안에서 "사진 표지 / 3칸 카드 / Before·After"를 연속 반복하지 않는다 (운영 문서 지침).

### 6. 흐름 설계 (유동) — 템플릿을 고르지 말고 질문으로 정한다

모범 사례 두 편의 흐름은 이렇다. **참고용이지 정답이 아니다.**

- 주변평가(8P): 사진 표지(질문+오답) → 공감 짤 + 흔한 답 → 면접관이 보는 것 3가지 → 칭찬↔행동 표 → 실제 답변 → 빈칸 3줄 → 서비스
- 공백기(6P): 사진 표지(면접관 대사+속마음) → 흔한 답 짤 + 면접관 다음 질문 → 답변 순서 3단 → BEFORE/AFTER → 예외 상황 + 하지 말 것 → 다크 체크리스트 CTA

새 콘텐츠는 아래 질문에 답하면서 장을 배치한다.

1. **독자가 첫 장에서 "내 얘기다"라고 느낄 장면은?** → 표지(면접관 대사·속마음·오답 중 하나)
2. **지금 독자는 무엇을 잘못 알고 있거나 막혀 있나?** → 공감/문제 장 1장(짤+quote, 또는 table, 또는 xlist)
3. **관점을 바꿔줄 핵심 한 문장은?** → 그 문장이 결론이 되는 장 1장(cards/flow)
4. **그걸 눈으로 증명할 실물은?** → 비교·예시 장(compare/pairs/bar). 설명보다 실물을 우선.
5. **독자가 바로 해볼 행동은?** → worksheet 또는 std_cta 체크리스트
6. **제품이 들어갈 자리는?** → 취준팁은 마지막 1장만. 프로모션은 4장 이후부터 자연스럽게.

규칙: 한 장 한 메시지, 6~8장, 같은 블록을 연속 3장 이상 반복하지 않기, 직전 게시물과 표지 방식이 겹치지 않게.

### B. 취준팁 (자소서·경험정리·운영법) 6~7P

**구조**: 공감(오해 깨기 ❌) → 정보 → 구조/질문 4개 → 예시(BEFORE/AFTER 또는 합격 자소서 발췌) → 매핑 표 → 홍보 1장 → CTA.

실제 사례 두 개:
- 「"직무 경험이 없다"는 착각」: 사진 표지("아.. 직무 경험 없는데, 어떡하지?" / "불안한 당신을 위한 / 현직자의 경험정리 Tip") → 체크리스트 5행 + 네이비 박스 → 스텝 로우 4(관찰·문제·행동·결과) + 블루 결론 박스 → 질문 4개 번호 리스트 + 프로그레스 바 → BEFORE/AFTER 2단(핵심 강점 0/4 vs 4/4) → JD↔경험 매핑 표 + 좌측 보더 인용 → 홍보("커리어마이징에서는 / 이 모든 걸 무료로 할 수 있다고?") → 라디얼 CTA("댓글에 "경험정리" 남기면"). 라이트 에디토리얼(헤어라인 + 풋터 "다음 → …").

헤드라인에 ❌ 오해 깨기, 서브에 "No!! …하세요" 같은 구어 허용. 밈은 공감용으로만, 출처 캡션 필수.

#### B. 기능 리뉴얼 안내 (5장, 라이트 블루 그라디언트, 중앙정렬) — 면접
풀 로고 표지("기업별 맞춤형 / 이력서 기능 출시" + 날짜 "26.08.20") → 본문 3장(로고 아이콘 → 헤드라인 Bold 54 2행 → 목업 900×590 + 플로팅 카드 → 설명 3행 36px) → 마무리("새로워진 면접 기능, / 지금 바로 시작해보세요" + "프로필 링크에서 커리어마이징 접속하고 / 경험정리부터 자기소개서, 면접 준비까지 끝내세요." + 혜택 "면접 기능 리뉴얼 기념 / 전 계정 500 크레딧 증정").
본문 장 = "헤드라인(약속) → 화면 → 3행 설명(근거→기능→효용)". 예: "23-25년 대기업 면접 복기본 기반 질문으로 / 실전처럼 준비하세요" → "최근 {면접 복기 데이터}를 바탕으로 / 직무와 기업에 맞는 질문을 만들고, / {실제 면접 흐름}에 가까운 방식으로 답변을 준비하세요."

#### C. 리뉴얼 + 프로모션 (6장, 포토 다크) — 기업분석

### 2. 길이·형식

- 첫 줄이 피드에서 잘리므로 **첫 문장에 훅**(표지 헤드라인의 변주)을 둔다.
- 문단 사이 빈 줄, 섹션 구분은 "—" 한 줄. 불릿은 ✔ / 📌 / 👉 중 한 종류 위주로.
- 이모지는 캡션에서는 허용(📚 📌 👉 ✔ 🗓️ 💌 🔍 👀)하되 문장당 1개 이하.
- 길이: 취준팁 400~800자, 기업 전략 800~1,500자, 프로모션 300~500자.
- URL은 캡션에 넣지 않는다(비활성). **프로필 링크** 또는 **댓글 키워드 → DM** 동선. "더 많은 취업 정보는 @careermizing에서💌"로 닫을 수 있다.
- 마지막 줄 해시태그 4~8개, `#커리어마이징`은 끝에.

## 카피 전문 예시 (유형별 1편씩, Figma 원문)

새 카피를 쓸 때 톤·길이·구조의 기준으로 삼는다. `{블루}`는 포인트 색 span, `~~취소선~~`, `==형광펜==`.

### 1. 면접팁 7P — 「왜 당신을 뽑아야 하죠」 ([DESIGN] 20261015, Published)

**P1 표지(사진)** 채용 담당자 : / 다른 지원자랑 / 차별점이 뭔가요? — 혹시 아셨나요? 이 질문은 장점을 묻는 게 아니에요. — 출처 : 핀터레스트

| 실제 기출·빈도 | 근거 없으면 '대기업 공통 기출' 등의 단정 금지 |
| 합격 사례·성과 | 실제 자료·이용 권한 확인 전 외부 홍보에 사용하지 않음 |
| 가상 사례 | 본문에 반드시 '가상 예시' 표시 |
| 기능/가격/혜택 | 게시 당일 앱 기능·정책 확인, 추정하지 않음 |
| 내부 데이터 | 직접 열람하지 않은 수치는 "보유·검증했다고 주장 금지" |
| 과거 통계 | "과거 조사 수치이므로 올해 채용 전체에 일반화하지 않는다" — 본문 미노출 |

Evidence Pack 관행: 출처마다 **열람일** 명시, "확인 Fact / 취준생 의미 / 콘텐츠에 실제 사용할 근거 / 주의(확대 해석 금지)" 4항 기술.

# 13. `careermizing-content-review/SKILL.md`

## 커리어마이징 콘텐츠 검수

초안(카피 텍스트, 렌더 스펙 JSON, PNG, Figma 링크)을 받아 **운영 문서의 기준 그대로** 점검한다. 기준 문서는 `../careermizing-content/references/`에 있다. 평가는 "좋다/나쁘다"가 아니라 **어느 장의 어느 문장이 어떤 규칙에 걸리고 어떻게 고칠지**로 쓴다.

### 순서

1. 유형을 판정하고(취준팁·면접팁·정보성 / 프로모션 / 기업별 / 기능 홍보) 해당 `content-types/*.md`와 `brand-voice.md`, `qa-checklist.md`를 읽는다.
2. 입력이 Figma 링크면 `get_metadata`로 섹션·프레임 이름을, `get_design_context`로 장별 텍스트·색·폰트 크기를 뽑는다(`figma-design-to-code` 가이드 로드 후). PNG면 직접 보고 읽는다. JSON 스펙이면 `scripts/render_carousel.py`로 렌더해서 본다.
3. 아래 다섯 축으로 점검한다. 각 항목은 **장 번호 + 원문 인용 + 걸린 규칙 + 수정안** 네 요소를 갖춘다.
   - **Hook/Story**: 표지가 면접관 질문·속마음·실제 상황에서 시작하는가, 한 장에 메시지 하나인가, 7P 역할 흐름(질문→약한 답→이유→프레임→실제 발화→주의→워크시트)이 끊기지 않는가, 직전 콘텐츠와 레이아웃(사진 표지/3칸 카드/Before·After) 반복인가.
   - **Fact/Safety**: 단정·보장·공포 표현, 근거 없는 기출·수치, 언론 해석↔공식 발표 혼동, 오래된 공고의 현행 표기, NCS 예시의 기출 포장, 가상 예시 표시(※) 누락, 출처 캡션 누락, 민감 정보 공개 유도, 없는 성과 창작 권유.
   - **Product/Offer**: 기능명 공식 표기, 가격·할인율·기간·기존 고객 안내, 무료 조건(Workspace·유형별/계정별 1회), 선착순 문구, 미배포 기능, 제품 노출 위치(P1~P3 없음), Main CTA 1개.
   - **Design**: 캔버스 비율 통일, 포인트 블루 1종, 기업 CI는 포인트만, 헤드라인 2행(표지 3행)·본문 ≥ 34px·면책 ≥ 21px, 마진 64~80, 페이지 번호 "0N / 0M" 전 장, 브랜드 마크 위치, 캡처 고지 문구, `CareerMizing` 철자, 템플릿 복제 잔여물(다른 기업명·이전 캐러셀 카피·"DART 공시 기반 " 같은 미완 문장).
   - **Caption**: 유형별 구조, 첫 줄 훅, URL 미삽입(프로필/댓글 동선), 해시태그 4~8개 + `#커리어마이징`, 본문과 모순 없음, 기존 고객 안내(프로모션).
4. 한국어 자연스러움: 번역투·접속사 남발·사무적 개념어·교과서 문장을 짚고 "행동이 보이는 말"로 바꿔 쓴다.
5. 결과를 아래 형식으로 낸다. 확인할 수 없는 사실(현재 가격, 기능 배포 상태, 내부 수치)은 **"확인 필요"**로 남기고 추정하지 않는다.
